# Сценарий записи экрана — Safe Sweep для WaiWai

Это пошаговый сценарий для записи экрана и голоса, которую требует тестовое задание WaiWai (Product Hacker). Запись идёт **без монтажа** — одна сплошная запись от начала до конца. Подойдёт OBS, QuickTime, Zoom или любая программа записи экрана с захватом голоса.

> Общая длительность: около 30–45 минут (запись можно вести и короче 90 минут — главное, чтобы прозвучали все ключевые моменты ниже).

---

## Подготовка (до старта записи)

1. Закройте лишние вкладки и уведомления, чтобы не отвлекали.
2. Откройте редактор/терминал в папке проекта: `E:\dev_projects\tests\Test 2`.
3. Убедитесь, что микрофон работает и захватывает ваш голос.
4. Включите запись **до** первого обращения к AI / открытия продукта.

---

## Сценарий по минутам

### Блок 1. Введение (1–2 минуты)

Говорите вслух, глядя в камеру или на экран:

- **Какое задание выбираю:** «Задание 1 — Игра наоборот. Беру классический сапёр и переверну правило: мины будут видны, а найти нужно безопасные клетки.»
- **Для кого продукт:** «Для людей, которые любят короткие головоломки на пару минут — в перерыве, в метро, на телефоне.»
- **Что хочу проверить первым:** «Главное — чтобы новое правило считывалось за секунды без инструкции. Если игрок смотрит на поле и сразу понимает „не трогай красное, открой остальное" — правило работает.»
- **Что режу ради 90 минут:** «Никакого логина, мультиплеера, онбординга. Только игра, победа/поражение и мгновенный рестарт.»

### Блок 2. Сборка с AI (основная часть)

Показывайте экран, где вы работаете с AI-инструментом (Droid / Claude Code / другой). Рассуждайте вслух на каждом шаге:

- **Что просите у AI:** озвучивайте запрос — «сделай реверсивный сапёр, мины видны красным, клик открывает безопасные клетки, числа показывают соседние мины».
- **Что принимаете из ответа:** «Ок, сетка через CSS Grid — хорошо, оставляю. Анимации поп-апа при открытии — оставляю.»
- **Что режете:** «Звуковые файлы не нужны — генерирую через Web Audio API, чтобы не тянуть зависимости. Логин и таблицу лидеров с сервером — выкидываю, не успею за 90 минут.»

### Блок 3. Ошибка AI — обязательно вслух (ключевой момент)

Когда AI сделает что-то не так, **обязательно скажите об этом вслух**:

- «Стоп, AI сгенерировал поле как обычный сапёр — мины спрятаны. Это ломает всю идею наоборот.»
- «Как заметил: при первом рендере нет красных бомб, клетки выглядят как классический сапёр.»
- «Как чиню: прошу AI сделать мины видимыми с первого кадра и убрать логику „первый клик безопасен". Проверяю — теперь мины светятся красным сразу.»

> Это самый важный момент для WaiWai — они хотят увидеть, что вы контролируете AI, а не принимаете первый ответ вслепую. Запомните примерную минуту записи, где это произошло (для ответа в анкете).

### Блок 4. Проверка продукта в браузере

Откройте `index.html` (или GitHub Pages ссылку) и проговорите проверку механик:

- «Видно поле, мины горят красным — правило понятно сразу.»
- «Кликаю безопасную клетку — открывается с числом, число совпадает с количеством соседних мин.»
- «Кликаю клетку без соседних мин — открывается каскад.»
- «Правый клик — ставится флажок, ещё раз — снимается.»
- «Кликаю мину — взрыв, экран поражения, кнопка попробовать снова.»
- «Открываю все безопасные — победа, конфетти, время, кнопка играть снова.»
- «Переключаю сложность: Easy 8×8, Medium 12×12, Hard 16×16 — поле меняется, таймер сбрасывается.»
- «Проверяю на мобильном размере — клетки скейлятся, горизонтального скролла нет.»

### Блок 5. Финал (1–2 минуты)

- **Покажите продукт целиком:** прокрутите поле, покажите победу или поражение, переключите сложность.
- **Назовите один шаг на завтра:** «Завтра бы добавил таблицу рекордов с именами и ежедневный челлендж — одно поле на всех в этот день, чтобы был повод возвращаться.»
- **Остановите запись.**
